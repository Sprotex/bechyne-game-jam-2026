# Room authoring

Each room scene attaches `scripts/rooms/room.gd` and declares its `room_title`. The level reads that title for the HUD. Add a `Sprite2D` named `Background` and keep it at the artwork's native size. Set the room's `walkable_outline` points in background pixels; the room builds physical boundary segments along that outline. Use a distinct outline for each artwork rather than fitting every room to one shared rectangle. Add room-specific `StaticBody2D` furniture collisions where the art has solid furniture.

To add a door, instance `scenes/objects/room_exit.tscn`, set its wall side and position on the walkable outline, then set its destination scene path and destination arrival ID. The room perimeter stays solid, including at doors: travel requires the interact action rather than walking outside the artwork. The trigger is offset toward the walkable side; `opening_half_width` controls its span. When adjacent door triggers overlap, only the nearest eligible exit shows its prompt and handles interaction. Add a `Marker2D` below `Arrivals` with that ID as its name, on clear interior floor with enough space for the whole player capsule. The reverse door is a separate exit in the destination room. Destination scene paths avoid cyclic `PackedScene` references while keeping room links directly editable in the Inspector.


The persistent player camera follows the player and uses each background texture's world rectangle as its limits. `WorldFrame` fits the background height to the viewport with uniform zoom, preserving its aspect ratio; wide rooms scroll horizontally. Keep room art, collision geometry and arrivals in native background pixels rather than scaling them separately. The CanvasLayer HUD stays anchored to the screen. The player position marks the feet; the sprite and collision shape sit above that point. Horizontal speed is 433 and the adjustable vertical speed ratio defaults to 0.55 for the high angle room art.

The player's `Sprite2D` node is an `AnimatedSprite2D` using `assets/gfx/player_walk/player_walk_frames.tres`. Walking uses the 16 supplied frames at 16 FPS; sprint doubles animation speed. Footstep contacts are frames 1 and 9 (zero-based 0 and 8), using the isolated `footsteps` registry clip. Animation and footsteps require actual movement after collision handling and stop when movement or player controls stop.

## Persistent pickups and flags

Instance `scenes/persistent_pickup.tscn` for a collectible, give it a stable unique `item_id`, and set the displayed `item_label`. Interacting sets that ID in the level's flag store and hides the pickup. Other gameplay code can check `Level.has_flag("key.front_door")` to gate a door or dialog. Flags persist while the level is active, including across room changes, and reset when a new game session starts.
